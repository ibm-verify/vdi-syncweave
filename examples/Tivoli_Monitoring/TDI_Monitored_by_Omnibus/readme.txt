Overview:
This example demonstrates possible integration between SDI and Netcool/OMNIbus. The example implements monitoring SDI using OMNIbus.

For this scenario the Server Notifications Connector was used as it provides the ability to listen to SDI Server events.
EIF Connector is used to send generated events to OMNIbus.

These files are included in the example:
	readme.txt - provides informatino about the example.
	EventPropertFile.properties - Determines the set of events that are received by the Server Notifications Connector.
	tdi_omnibus.xml - SDI Configuration file for the example.
	
Prerequisites:
The following software components are needed for the example:

1. IBM Tivoli Netcool/OMNIbus
2. IBM Security Verify Directory Integrator
3. Probe for Tivoli EIF 
Note: the "log.jar" and "evd.jar" file that go with the EIF probe must be copied to the jars directory of SDI.

This demo provides one AssemblyLine. Here is a brief description of it:
"TDI_Monitoring" - This AssemblyLine monitors the SDI Server and listens to SDI events. Then they are sent to OMNIbus.

To run this demo:
1. Start the IBM Security Verify Directory Integrator Config Editor.
2. Import the tdi_omnibus.xml file.
3. Modify the "EventPropertiesFile" so that it matches the set of events that you want to receive. (For more detailed information refer to the "Work with properties" section)
4. Open the "AssemblyLine" branch.
5. Select "TDI_Monitoring" AssemblyLine.
6. Modify the "ServerLocation" and "ServerPort" values of the EIF Connector so that you send the events to the right EIF probe.
7. Click "Run"


Here is a brief description of "TDI_Monitoring" workflow:
1. The Server Notifications Connector listens to events generated by the SDI Server.
	-When "TDI_Monitoring" AssemblyLine is started you can receve events like AssemblyLine events, Config Instance Events, etc. If you start any other AssemblyLine you will be notified that it has started (as long as you haven not disabled receiving this event in the properties file).
2. These events are sent to OMNIbus via the EIF Connector.
	-Events that are captured by the Server Notifications Connector are mapped to match the format of a EIF event and sent to OMNIbus.
	

Work with properties:
The property file has the following structure -> key=value
EventPropertFile.properties provides a default set of events that will be received by the Server Notifications Connector. However, a few things should be considered in order to avoid any misunderstanding. 
To make it clear look at the following diagram showing the default set of events:

|->event.all
|	|->event.ci.all
|	|	|->event.ci.start
|	|	|->event.ci.stop
|	|->event.ci.fileUpdated
|	|->event.al.all
|	|	|->event.al.start
|	|	|->event.al.stop
|	|->event.server.stop
|->event.hasCustomNotifications
|	|->event.customNotifications

If you enable some type of event, then all subevents will be received no matter if they are set to "true" or "false". This means that if you have 
event.ci.all=true
event.ci.stop=false
the event.ci.stop event will be received despite it is set to "false".

To receive custom notifications you must set the event.hasCustomNotifications to "true". Then you need to specify the set of events that will be received. Note that all custom events sent by SDI are prefixed with "user.". This means that if you send a custom event of type "myType" then you must set:
event.customNotifications=user.myType
To specify more than 1 custom events use ";" to separate them.
To receive all custom events set the value of event.customNotifications to "*".

There is a configuration located at examples\Tivoli_Monitoring\TDI_Monitored_by_ITM that sends custom notifications. You can use custom_notifications_server.xml configuration file to test sending custom events to OMNIbus. For more detailed information refer to the readme file at examples\Tivoli_Monitoring\TDI_Monitored_by_ITM.
Note that if "TDI_Monitoring" AssemblyLine is running all other specified events will be received as well.
