This example demonstrates how to use the IdML suite of Components to generate an IdML book. 
The shown Components are: Open IdML FC, IdML Ci and Relationship Connector, Rolling IdML FC and Close IdML FC.
These files/folders are included in this example:
 � input.csv (a comma-separated file containing data for different computers),
 � generate_idml.xml (configuration),
 � readme.txt (this file)
 � /sample_output (contains 2 files that can be compared with the ones generated by this example).

To run this example you must:
 � InstalSyncWeaveor.
 � Import the supplied configuration.

This package contains a single SyncWeave configuration file - generate_idml.xml, 
which consists of two AssemblyLines:
 1. 'CreateIdMLBook_1' AssemblyLine: 
It has a File System Connector in Iterator mode (�ReadCSV�), which reads data from the input.csv file and maps it 
to attributes in the work entry. The Open IdML FC in the Flow section will create the needed book ('demoBook') and 
share it for the other IdML Components. This will be performed on the first AL iteration, and on each subsequent 
one, the FC will only check if the book has not changed. Since it has not, it will just pass the control to the 
following Connector. When the AL terminates this FC will close the IdML book and perform its validation. The three 
IdML Ci and Relationship Connectors add artifacts (two CIs and one Relationship) to the IdML book on each AL 
iteration. The 'addComputerSystem' creates a sys.ComputerSystem CI, the 'addOperatingSystem' creates 
sys.OperatingSystem CI and 'addInstalledOn' - an installedOn Relationship. The CDM meta-data they need, is 
provided locally as a JAR file. If you want to try the other supported CDM source (a remote IT registry system), 
you need to check the 'Use IT registry for CDM' option in the Advanced section of every Connector and provide 
information how to connect to IT registry in the below fields. 
The Rolling IdML FC will check if 15 artifacts (both CIs and Relationships) have been accumulated to the IdML 
book or if its size has reached 10 KB. If any of these conditions has occurred, it will close the current 
IdML file and open a new one for writing.

 2. 'CreateIdMLBook_2' AssemblyLine: 
This AssemblyLine offers the same functionality as 'CreateIdMLBook_1', but uses a different structure. 
While the 'CreateIdMLBook_1' is a normal Feed-Flow AssemblyLine where the data is retrieved from the �ReadCSV� 
Connector, the 'CreateIdMLBook_2' AssemblyLine is driven by a Loop Component getting data from a File System 
Connector.
The second difference is that this AL uses a Close IdML Function Component, which closes the IdML book and returns 
its contents.
Also, this AssemblyLine does not store the generated IdML document as a file, but keeps it in memory (as an IdML 
snippet) and displays it in the log. 
Finally, this AL does not use the Rolling IdML FC. This is because the AssemblyLine works with an in-memory IdML, 
which means that rolling is not supported. 
Examine both AssemblyLines to get an idea of the two use cases.

The configuration of any of the IdML Components can be seen by selecting SyncWeave CE  -> 
'AssemblyLine' section -> 'CreateIdMLBook_1'/'CreateIdMLBook_2' AssemblyLine -> 'OpenBook'/'addComputerSystem'/
'addOperatingSystem'/'addInstalledOn'/'RollBook'/'CloseBook', double clicking on it and selecting the Connection tab.

To run the demo:
 1.	Start the SyncWeave CE.
 2.	Select 'File'->'Import'.
 3.	Choose 'Configuration' and specify the path to the generate_idml.xml 
 (e.g. <install_dir>/examples/cdm_components/generate_idml/generate_idml.xml) in the next panel.
 4.	Click 'Finish'.
 5.	Go to the 'AssemblyLines' section.
 6.	Select the 'CreateIdMLBook_1'/'CreateIdMLBook_2' AssemblyLine.
 7.	Click 'Run'.
 8.	Check in the log if the AssemblyLine has run successfully.
 9.	For 'CreateIdMLBook_1' compare the generated IdML files with those in /sample_output (only the timestamps 
	should differ).
	For 'CreateIdMLBook_2' examine the IdML snippet displayed in the log.

	
The result of this example is the generation of an IdML file containing different Configuration Items and 
Relationships. This file can later be imported to a product supporting IdML, such as Tivoli Application Dependency 
Discovery Manager or Tivoli Business System Manager, transferring all of its information. However, SDI offers the 
ability to register these elements and their source tokens for usage by other tools and products via the IT 
Registry Components. They include the Init IT registry FC and IT registry Ci and Relationship Connector, which are 
designed to make use of the different IT registry 1.1 services and register the artifacts directly in the IT 
registry database.	
Here are the steps needed to modify the IdML example to use IT registry, instead of an IdML file:
Note: The modifications will be applied to the 'CreateIdMLBook_1�  AssemblyLine. The steps for changing the 
'CreateIdMLBook_2� AL are similar.

1. Click on the OpenBook Function Component and change its inheritance from �Open IdML Function Component� to 
�Init IT registry Function Component�. Thus it will behave as its analog from the IT registry suite from now on.
The converted Components can also be renamed to better denote their new usage, but for the purpose of this example 
we will leave them as it is.
2. Supply the needed IT registry parameters in the Advanced section of the FC. Since the same action should be 
performed for each converted Component, it will be easier to place the IT registry parameters in the 
etc/it_registry.properties file. From now on, we will assume the properties file is being used.
3. Map the $mssGuid attribute in the Input Map of the FC (it was not present before the conversion of the FC).
4. Make sure the Use IT registry for CDM option is checked (this should happen automatically when you change the 
inheritance) and populate the CDM version field by pressing the Get CDM version button.
This way you can be sure that the CDM version used by the Components matches the one used by IT registry.
5. Click on the addComputerSystem Connector and change its inheritance from �IdML Ci and Relationship Connector� 
to �IT registry Ci and Relationship Connector.�
6. Map the $mssGuid attribute from the Input Map of the OpenBook FC to the Output Map of the addComputerSystem 
Connector.
7. Rename the attribute in the Input Map of the Connector from conn["$id"] to conn["$guid"]. The reason is that 
IT registry Components work with hexadecimal identifiers called GUIDs, while the IdML ones rely on string 
identifiers (containing both numbers and letters) called IDs.
8. Repeat steps 4 to 6 for the addOperatingSystem Connector. 
9. Repeat steps 4 to 5 for the addInstalledOn Connector (there is no need to edit the attributes in the Input Map 
of the Connector).
10. Delete the RollBook FC, since it has no meaning in the IT registry scenario. 
Note: If the AssemblyLine contains a Close IdML Function Component, it should also be removed, since it has no 
equivalent in the IT registry suite.
